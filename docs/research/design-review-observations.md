# Design review of Encantis (forwarded from another session, written against main as of PR #35)

STATUS: these are PROPOSALS the owner has NOT decided on. Do not implement them and do not write them into the reference as the language. Use this file only for its FACTUAL observations about how main behaves today (each must be re-checked with the CLI): where the reference disagrees with the compiler, those facts must be fixed in the reference (describe current behaviour) or reported as a compiler bug / owner question by the usual rules.

Factual observations to verify (from the review):
1. `[N]T` meaning depends on position: as a struct field in memory it is packed in place; as the element of a pointer or slice it is a table of row pointers (`*[2][3]i32` is not a pointer to `[2][3]i32`; packed 2D is `*[2x3]i32`). Generic substitution: `Vec([3]i32)` becomes a table; lib/vec.ents tells users to wrap the row in a struct. The rule touches §2.5 Nesting, §4.8, §8.5, §8.7, "the one exception" in §9.6, `.wid`, `memzero`.
2. Literals in memory: four ways (implicit layout where a pointer is expected, `mut lit`, `&lit`, `data x = lit`).
   - `let q = mut [1:u32, 2, 3]` is a register `[3]u32`, and `let r = mut 5:u32` a plain `u32`, while §1.5 says both become `*mut`. `&[1:u32, 2, 3]` is a `*mut [3]u32`.
   - `data cells: *[3]i32 = [...]` gives `*[3]i32` (annotation = pointer type); `data pool: Pool = mut (...)` gives `*mut Pool` (annotation = pointee type); `data p: *mut Pool = mut (...)` gives `*mut *mut Pool`.
   - docs/memory.md, docs/agent-guide.md, §9.1 and CLAUDE.md ("def ... scalars only") disagree with each other; three write static buffers as `def buf:[4096]u8`.
   - `&"abc"` is an error today.
3. Templates: `writev(["Welcome ", name, " who likes ", color, "."])` compiles to the same layout as the backtick template.
4. Optionals: `?` exists only for pointers, slices and host references. An unproven index gives a storable `?T` for pointer and slice elements but an optional that must be resolved on the spot for numbers and rows. `func keep(comptime T: type, x: ?T)` called with u32 fails inside the instance: `cannot make u32 optional … in keep(T = u32)`. The host boundary adds a trap the source does not show.
5. `[!]T`/`*[!]T` (two spellings of one type), `*[?]T` (laid out but not readable), `[!x!]T`, `[5x?]T` exist.
6. Overloads: §3.4's rules for choosing among same-named functions; `gt(x, 2.5)` with x: u32 quietly converts x. Host types are distinct by name across the whole program (two libraries that each declare `type Handle = host` share one type).
7. `let` scoping: normally visible to the end of its function (a let inside an if can be read after it); a let in the first branch of `if let` is visible only there; a plain host `let` in a branch or loop body is visible only in its block. A `let` of `?*T` with no value is uninitialized (in a loop it keeps the last pass's value) but a `let` of `?Canvas` with no value is none on every pass. Which `0` means none: `0`, `-0`, `(0)`, a branch's value, a def of 0, a value parameter given 0, but not `0 + 0` or `-(0)`.
8. Small: destructuring forms `set`, paren-less `let a, b =`; §6.2 signature patterns are not parsed by the grammar. Casts `i32(x)` and `x as i32`; generic `T(x)` has a special error. Type views `p.u32` (258 uses, all `p.u8[i]` form = `p as [*]u8`), planned load/store meaning and `p.(MyStruct)`. `memzero(p)` = `p[..] = 0`, `memset` = range fill; `.wid` = sizeof(T). `0d` dozenal literals and multi-codepoint `'ok'` tuples have no uses. An undocumented `^T` boundary pointer exists. `inline` is parsed and then ignored. Enums, function values, closures, struct patterns and saturating operators are not implemented.
